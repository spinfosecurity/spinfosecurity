# For employers / interviewers

This toolkit is a portfolio sample for **IT Services / L2** work with an engineering bar: first-principles triage, measurable onboarding, fleet correlation, and escalations that respect senior time.

## Map to the role

| Role need | Tool |
|-----------|------|
| Diagnose complex endpoint / network issues | `why-broken`, `dns-truth`, `path-quality`, `auth-clock` |
| Fix without cargo-cult reboot | `stack-reset` |
| Disk / performance context | `disk-reclaim` |
| Proactive user enablement | `meeting-preflight` |
| Separate path vs app | `reach-matrix` |
| Detect fleet incidents early | `fleet-fingerprint` |
| New-hire onboarding excellence | `time-to-work` |
| Security hygiene / data protection | `secret-hygiene` |
| Ticket quality + L3 escalation | `escalate-smart` |
| Cross-platform (Windows + macOS/Linux) | Bash ↔ PowerShell pairs |
| Knowledge / self-service | README + PRINCIPLES + `--help` |

## Best 5-minute review path

1. `PRINCIPLES.md` — design rules  
2. `bash/why-broken.sh` + `powershell/Why-Broken.ps1` — ranked diagnosis  
3. `bash/escalate-smart.sh` — how L3 should be briefed  
4. `bash/time-to-work.sh` — onboarding as a stopwatch  

## What this is not

- Not a domain-admin toolkit (no AD writes)  
- Not MSP RMM bloat  
- Not “print everything and hope”  

It is the scripting habit behind excellent support: **measure → rank → fix → prove → escalate only when needed.**
